- HME Wallet links: src/lib/hme-link.server.ts, hme-link-rules.ts (tested), api/public/hme-link/*. Trust the wallet's pocket number (rotates 1106→2105); a re-link while active must keep its pocket and every coin. hme_links rows = permanent history (trigger blocks deletes/edits; hme-link-history.ts). Why: dropped keys strand coins; the record must stay whole.
- P2P marketplace logic lives in src/lib/p2p.server.ts (reserve against the live HME-pocket balance, flag drops; release via pocket-send). Why: no custody; safety = on-chain checks + seller score.
- Every HME-pocket send needs the owner's Telegram tap (src/lib/pocket-send/AGENTS.md).
- Uniswap/PancakeSwap/PulseX pricing: src/lib/dex/AGENTS.md.
- /list: packages + rules only in src/lib/listing.ts (tested); applications server-written, reviewed at /admin/listings. Why: shown and stored prices must match.
- /account is the tabbed HME trading-pocket and settings surface; /wallet and /api-keys redirect into it, legacy vault code stays. Deposit/withdraw networks come only from src/lib/account/deposit-options.ts (pure, tested): deposits open only when coins can leave again (HME Wallet sends, Seeds swaps to TSD, or Seeds sends — PulseChain only). Why: Seeds must not act custodial; no deposit may be one-way.
- HME pocket receive addresses derive public child 0/0 from the wallet-submitted account xpubs; display native balances separately from settlement assets. Why: pocket rotation must not reuse static legacy derivation paths or mislabel trading liquidity.
- HME authentication helpers live in hme-auth.server.ts; verify ticket issuer/site, single-use nonce and expiry, send the Seeds site header, and resolve local accounts by the uniquely indexed hm_member_id before updating contact email. Why: credentials are site-bound and email changes must never merge or recreate accounts.
- Test files (*.test.ts) are excluded from the app tsconfig and run with `bun test`; never install @types/bun. Why: Bun globals override Workers fetch types and break the app typecheck.
- orders/trades/escrows/profiles are server-written only (no client INSERT/UPDATE grants); leg amounts are derived from immutable trade terms. Why: audit C1/C3 — settlement must never trust browser-editable rows.
- Every key-spending path goes through src/lib/settle-guard.server.ts (cumulative cap reserve, single claim per leg, payer-only send) and autosettle preflights both legs before sending anything. Why: audit C2/H2/H6.
- Ignite: ignite.functions.ts + nectarpay.server.ts, Peer Pay in ignite-peer.ts (tested) + ignite-peer.functions.ts; rows server-written; a seat is confirmed only in ignite-confirm.server.ts, which re-reads the NectarPay invoice (paid in full, Seeds' order id) and confirms with compare-and-set, via the signed webhook or throttled re-check; one live checkout per seat. Admins cancel via cancelIgniteSeat; cancelled seats never re-confirm (canConfirmSeat); refunds manual in NectarPay. Why: payment state never comes from the browser, a missed webhook can't strand a seat, no seat is paid or announced twice.
- /brand shows the supplied PDF as CDN page images + extracted text + the original PDF; its examples aren't implemented features. Why: reproducing the document must not change trading or sign-in.
- Pocket keys/chain I/O: src/lib/pockets/AGENTS.md.
- Transactional email: src/lib/email/AGENTS.md.
- Every route sets staticData.sitemap (true / false / "exclude-subtree" for private layouts); /sitemap.xml is derived from the router via src/lib/sitemap.ts. Why: new pages must make an explicit search-listing decision and private areas never leak into Google.
- Pre-HME accounts (no hm_member_id) join an HME membership only via src/lib/legacy-claim*.ts: first HME sign-in with a matching email gets a 30-minute single-use link emailed to that inbox, and redeem_legacy_claim attaches the member id atomically; never merge on email match alone, and back up into legacy_account_backups before deleting any account. Why: an HME account using someone else's email must not inherit their history or saved wallet.
- Telegram (TelegramCard): 15-min single-use hashed start code via t.me/seeds_notify_bot?start=; webhook needs the TELEGRAM_API_KEY-derived secret, private chats only. Alert buttons (telegram-actions.ts) are HMAC-signed per link+owner, act only from the owner's verified chat; revokes use hme-link-revoke.server.ts. Why: forged taps can't attach or revoke.
- Brand tokens live only in src/styles.css (:root = light, .dark = dark); --primary is the text-safe green, --action the Seed Green button fill; the logo is the supplied artwork via src/components/site/SiteLogo.tsx (CDN PNG pointers in src/assets/logo/), never retyped text. Ignite pages use the same tokens via .ignite-theme. Why: one brand source keeps light/dark legible and the mark unaltered.
- Header and footer render once in __root.tsx; every page body sits in `mx-auto max-w-7xl px-5` (narrow cards go inside it, left-aligned), wide tables scroll inside `overflow-x-auto`, and html reserves the scrollbar gutter; the desktop nav shows at lg+, below that a menu button. Why: page edges must not shift between routes or slide sideways on phones.
- Post-sign-in destinations go through src/lib/return-path.ts: every link to /auth passes `search.redirect` (protected layout passes location.href), /auth remembers it in session+local storage for 24h, /sso and /auth consume it via takeReturnPath; only same-site paths, never /auth or /sso, and a generic "/" never overwrites a specific page. Why: new visitors often leave to join Honest.Money and come back in another tab, and open redirects must be impossible.
- Members share referral links as seeds.honest.money/invite/{code} (inviteUrl); that route only 302s a cleanRefCode-validated code to honest.money/r/{code}?to=/ignite (old /register links 301 to /ignite). Why: the raw HME link is unreadable in emails, and HME must still count the click.
- Human API docs live at /api (src/routes/api/index.tsx, markets from PAIRS); machine endpoints stay under /api/public/v1 and /api/public/cmc; /api-docs 301s to /api. Why: one short address for developers; external callers keep the auth-bypassing /api/public prefix.
- Long legal pages use site/LegalDoc.tsx. Why: consistent layout.
- Seeds sends coins out only on PulseChain (see src/lib/pulse/AGENTS.md).
- Seeds AI rules live in src/lib/ai/AGENTS.md. Why: the engine and playbook have their own constraints.
- /admin is a layout (side menu) with child-route tabs; each child server fn still checks admin. Admin access changes only via set_admin_role (admin-users.functions.ts; rules in admin-users-rules.ts, tested): locked, HME members only, no self or last-admin removal, logged. Ignite admin emails (ignite-admin*.ts) are logged in ignite_admin_emails; payment links point to /ignite, never an old checkout. Why: access and payment emails must never be silent or repeatable.
- DemoBanner renders once in __root above the header (→ /coming-soon); remove at trading launch. Why: one switch.
- 2FA = sign-in service TOTP (two-factor*.ts); server trusts only session aal2+amr; 2FA levels need it; withdrawals need a link created after the newest verified factor (withdrawLinkState, re-checked at send); admin powers via admin-guard.ts requireAdmin. Why: browsers can't fake it; a hijacked sign-in can't add its own phone and withdraw.
- Setup guide = /welcome (onboarding.ts, tested); /account beforeLoad sends members with no profiles.onboarding_status there. Why: skippable once, stored server-side.
- /stats traffic = Seeds' own counter (site-traffic.ts; /api/public/track), read only via site_stats_* totals. Why: Lovable analytics isn't runtime-readable; never expose single visits.
