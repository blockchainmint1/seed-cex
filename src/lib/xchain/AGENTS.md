- Cross-chain swaps (THORChain + Maya) live in src/lib/xchain/: assets.ts (registry of every live pool except protocol-native tokens; per-network address rules in SWAP_CHAINS; memo shortcodes are per protocol and added only after a live quote proves them), safety.ts (pure memo/limit/vault rules, tested), router.server.ts (public-node reads). A route is send-ready only when memoSafe, limitOk and a 2-independent-server vault (and EVM router) check pass; public quote responses never include vault addresses. Why: a wrong memo or vault is an unrecoverable loss, and the same shortcode means different coins on THORChain and Maya.
- Sending lives in send.server.ts (orchestrator), send-rules.ts (pure: sendable coins, pilot switch, limits, progress mapping; tested), evm-router.ts (pure router calldata; tested) and send-io.server.ts (DOGE/BCH/XRP/TRON/SOL network I/O). Order is fixed: server re-quote with every check → re-quote at most 1% worse than shown → reserve_swap_send (one in-flight per pocket, per-swap/daily USD caps, in SQL) → decrypt key, verify it controls the pocket address → sign locally, store txid, then broadcast → wipe key. THORChain only; instant-access links only. Why: the browser's quote and amounts are never trusted, and no key is opened before the caps are reserved.
