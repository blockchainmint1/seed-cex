- Cross-chain swaps (THORChain + Maya) live in src/lib/xchain/: assets.ts (registry of every live pool except protocol-native tokens; per-network address rules in SWAP_CHAINS; memo shortcodes are per protocol and added only after a live quote proves them), safety.ts (pure memo/limit/vault rules, tested), router.server.ts (public-node reads). A route is send-ready only when memoSafe, limitOk and a 2-independent-server vault (and EVM router) check pass; public quote responses never include vault addresses. Why: a wrong memo or vault is an unrecoverable loss, and the same shortcode means different coins on THORChain and Maya.
- Sending lives in send.server.ts (orchestrator), send-rules.ts (pure: sendable coins, pilot switch, limits, progress mapping; tested), evm-router.ts (pure router calldata; tested) and send-io.server.ts (DOGE/BCH/XRP/TRON/SOL network I/O). Order is fixed: server re-quote with every check → re-quote at most 1% worse than shown → reserve_swap_send (one in-flight per pocket, per-swap/daily USD caps, in SQL) → decrypt key, verify it controls the pocket address → sign locally, store txid, then broadcast → wipe key. Instant-access links only. Into Maya only the MAYA_SEND_ASSETS allowlist (send-rules.ts) is sent; Maya delivery counts only a payout on the coin's own chain (Maya also lists CACAO payouts). Why: the browser's quote and amounts are never trusted, and no key is opened before the caps are reserved.
- TSD routes (TSD <-> any THORChain coin) go through TSD Bridge's partner API, never a Seeds-run bridge: tsd-route.ts (pure rules + bridge-answer checks; tested), tsd-bridge.server.ts (client), tsd-route.server.ts (resumable stage machine, claimed per step, txid stored before broadcast, never re-signed), gas.server.ts (Seeds gas wallet: separate KMS key, ETH shortfall only, caps reserved in reserve_gas_topup). USDC between legs always sits in the member's own EVM pocket; the swap leg reuses sendSwapFromPocket on tsd_routes.protocol (best quote of THORChain/Maya via legProtocols/pickLeg), falling back to the other network only on RouteUnavailableError (nothing reserved or sent). Why: one TSD issuer and reserve, and no step where Seeds holds member coins.
- Ethereum fees are checked before anything moves: routeGasUnits (tsd-route.ts, tested) counts the gas a route will spend, gasPreflight refuses to start when the member's pocket can't pay it and Seeds' gas wallet isn't covering it, and the same check runs again at the reserved stage. The Swap page shows the ETH estimate and the pocket's balance. Why: a member must never find out about a missing fee after their TSD is already with TSD Bridge.
- The setup guide's "Network fees" step (src/lib/fee-prep.ts, tested; live numbers in fee-prep.server.ts) offers "convert TSD to ETH" only when routeBlocker passes and the conversion's own Ethereum fee is paid (pocket or Seeds' gas wallet); otherwise it says to send ETH in. Base stays send-in while BASE_FROM_TSD is false. Why: never point a member at a conversion that will refuse to start.
- Swap history is one "My swaps" list (components/swap/MySwaps.tsx): listSwapSends drops any swap_sends row that is a tsd_routes leg, and listTsdRoutes carries that leg's txid for tracking. Why: a TSD swap is one swap to the member, never two rows.
- The "2 independent servers" vault check counts one answer per distinct node id (independentAnswers in safety.ts, tested; ids from /cosmos/base/tendermint/v1beta1/node_info); a server that can't be identified doesn't count. Maya's second server is Liquify's public node (router.server.ts PROTOCOLS) until Seeds runs its own; THORChain servers come from thornodeEndpoints (nodes.server.ts) and backupOnly entries are left out of the check. Why: two URLs for one machine must never pass as two confirmations.
- A swap paying anywhere but the member's own pocket (isOwnPocketDestination) needs 2FA on, a code in the last 10 minutes and a Telegram Approve tap (send_approvals purpose swap_out, spent with the same coin/amount/from/to). Why: an outside payout is a withdrawal.
- TSD Bridge status notifications arrive at /api/public/tsd-bridge/webhook (rules in tsd-webhook.ts, tested: HMAC of timestamp.rawBody with TSD_BRIDGE_WEBHOOK_SECRET, 5-minute window, order.id must be a full id); a valid one only calls advanceRoute for the matching tsd_routes row, which re-reads the order from TSD Bridge's API. The every-minute job stays the record of truth. New bridge orders are created with TSD_BRIDGE_WEBHOOK_API (the key carrying the callback link) when set; getBridgeOrder tries that key then WRAP_ISSUER_API_KEY, moving on only on 404 (bridgeReadKeys, tested). Why: notifications are best-effort and never retried; nothing in a body may move coins.
