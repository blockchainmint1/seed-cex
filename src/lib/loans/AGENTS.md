# Seeds Lend (src/lib/loans)

- P2P loans at /loans (unlinked, noindex, sitemap false until beta access exists): rules.ts (pure, tested: limits, flat term interest, collateral, LTV health, liquidation only when the fresh newest price AND the median of the last 6 price checks cross the line, 72h default grace, payout split lender → Seeds fee → borrower, negotiation turns), escrow.ts (pure, tested + checked on the TXC node: one 2-of-3 P2SH lockbox per loan, keys in order borrower, lender, Seeds — Seeds' key is the TXC lock KMS key; borrower+Seeds return, lender+Seeds pay out, borrower+lender work without Seeds), loans.server.ts (engine), loans.functions.ts (server fns), /api/public/jobs/loans (cron tick). Why: collateral is never pooled or re-lent, and a lockbox can only ever pay the two members by the stored terms. Seeds also holds both members' pocket keys, so never claim Seeds alone can't move a lockbox (audit L2).
- Seeds' only fee is on liquidation/default (fee_pct stored per loan), taken only from the borrower's leftover after the lender is made whole; returns and repayments pay Seeds nothing. Why: Bobby's rule — Seeds never takes a cut of a loan.
- Loans, proposals, offers, events and price marks are server-only tables (no browser grants); agreed terms, keys, lockbox and a signed payout are frozen by the loans_guard trigger; loan_events is insert-only. Every lockbox payout claims escrow_purpose with compare-and-set first (liquidate/default only while no repayment has started), is built from stored terms, stored before broadcast and re-broadcast from the stored hex. Why: one payout per lockbox, and a repayment in flight can't be liquidated under it.
- Pocket sends (collateral, funding, repayment) use send_approvals purposes loan_collateral / loan_funding / loan_repay (Telegram tap, continueLoanSend); funding/repay start with a compare-and-set stamp; collateral counts at 3 confirmations, funding/repayment via checkSentLeg + confirmationsNeeded; a vanished repayment reopens the loan. Real sends and loan creation are beta-tester only (both parties) for now. Why: same money-path rules as the rest of Seeds.
- Seeds Lend is OFF: rules.ts LENDING_OPEN=false refuses every offer, proposal, accept, collateral/funding send and refresh (repayments still allowed); the page shows a notice and the public market returns no offers. Collateral will move from TXC to BTC and ETH (Bobby); the TXC lockbox stays only as reference. Any rebuilt lockbox must carry audit L3 (pick inputs by value, skip dust, cap inputs, follow-up payout for leftovers), L8 (only rebroadcast when the node can prove the payout is missing) and an AWS alarm on its signing key. Why: lending isn't safe to run until the rules are reworked.
- Funding/repayment sends store their txid on the approval before broadcast (refuse to broadcast if that write fails); stuckSendStep (tested) adopts that txid, and reopens a started send only when it provably never went out. The tick settles a stuck repayment before any liquidation/default check. Why: audit L1 — a paid loan must never be liquidated.
