# Seeds Lend (src/lib/loans)

- P2P loans at /loans (unlinked, noindex, sitemap false until beta access exists): rules.ts (pure, tested: limits, flat term interest, collateral, LTV health, liquidation only when the fresh newest price AND the median of the last 6 price checks cross the line, 72h default grace, payout split lender → Seeds fee → borrower, negotiation turns), escrow.ts (pure, tested + checked on the TXC node: one 2-of-3 P2SH lockbox per loan, keys in order borrower, lender, Seeds — Seeds' key is the TXC lock KMS key; borrower+Seeds return, lender+Seeds pay out, borrower+lender work without Seeds), loans.server.ts (engine), loans.functions.ts (server fns), /api/public/jobs/loans (cron tick). Why: collateral is never pooled or custodial, and no single party — Seeds included — can move a lockbox.
- Seeds' only fee is on liquidation/default (fee_pct stored per loan), taken only from the borrower's leftover after the lender is made whole; returns and repayments pay Seeds nothing. Why: Bobby's rule — Seeds never takes a cut of a loan.
- Loans, proposals, offers, events and price marks are server-only tables (no browser grants); agreed terms, keys, lockbox and a signed payout are frozen by the loans_guard trigger; loan_events is insert-only. Every lockbox payout claims escrow_purpose with compare-and-set first (liquidate/default only while no repayment has started), is built from stored terms, stored before broadcast and re-broadcast from the stored hex. Why: one payout per lockbox, and a repayment in flight can't be liquidated under it.
- Pocket sends (collateral, funding, repayment) use send_approvals purposes loan_collateral / loan_funding / loan_repay (Telegram tap, continueLoanSend); funding/repay start with a compare-and-set stamp; collateral counts at 3 confirmations, funding/repayment via checkSentLeg + confirmationsNeeded; a vanished repayment reopens the loan. Real sends and loan creation are beta-tester only (both parties) for now. Why: same money-path rules as the rest of Seeds.
