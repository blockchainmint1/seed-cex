# TON -> USD₮ on TON (STON.fi) and USD₮-on-TON sends

- Pinned Tether USDt master and comment/address checks live only in pockets/ton-payment.ts (browser-safe); STON.fi contracts and Seeds-built message bodies remain in pockets/ton-jetton.ts (tested). Quotes supply price only after checkStonQuote validates pinned contracts; Seeds writes messages itself (member = own TON pocket, minimum = shown less 1%). Why: invoice parsing must work without wallet SDKs in the browser, and no outside payload is signed as-is.
- All TON messages go through signAndSendTon (ed-send.server.ts): toncenter + TONAPI agree on the W5 wallet and seqno, fee estimated and capped before the KMS unlock, id recorded before one broadcast. USD₮ withdrawals (withdraw kind ton_usdt) keep every withdrawal gate; spend reads need toncenter's get_wallet_data (owner + master checked) to equal TONAPI's balance. Why: one audited signing path for every TON send.
- ston.server.ts: own-pocket swap, no Telegram tap (Bobby's HC2 choice), one open per member, signed minimum = stonMinimum (≥99% of Seeds' fresh quote, never the browser's number alone; ston/rules.ts, tested), per-swap/24h USD caps via reserve_ton_swap (swapLimitsFor) (ton_swaps, server-only, txid/terms write-once, no deletes), done only when the pocket's USD₮ grew by ≥ the minimum since the noted baseline; never re-sent. Gated by the TON stage (edSendBlocker "TON"; testers now). Why: same no-pay-twice rule as every swap.
- Native TON withdrawals are confirmed by tonTraceStatus (ed-confirm-rules.ts, fixture cut from a live TONAPI trace): payment = the destination's child transaction's in_msg value; failure only from an aborted root or the root's action_phase (skipped/failed); everything else waits. USD₮ sends need 0.13 TON up front (usdtFeeAllowance). Why: audit TA1/TA4 — TONAPI traces have empty out_msgs, and a paid send marked failed could be paid twice.
