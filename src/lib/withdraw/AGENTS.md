# Withdrawals

- Seeds-signed withdrawals for every coin live here: catalog.ts (coins + networks Seeds can sign; keys match deposit-options; tested), rules.ts (pure readiness, email-code digests, amounts; tested), send.server.ts (address checks, balance reads, one signer per kind), withdraw.server.ts (flow), withdraw.functions.ts. One rule set for every coin (Bobby, Nov 20 2026): the wallet link must be newer than both the newest verified authenticator and profiles.telegram_verified_at (set only by a profiles trigger; null while connected = unproven, re-link); each withdrawal needs an email code bound to an HMAC of the exact coin/network/units/address/tag (withdrawal_email_codes, single use, 10 min, 5 tries, via use_withdrawal_email_code), a fresh session TOTP, and a send_approvals 'withdrawal' Telegram tap. reserve_withdrawal stores it as 'approving'; the tap is spent and approve_pocket_withdrawal starts the level's hold; the scheduled job (/api/public/jobs/pulse-withdrawals, path kept) re-checks everything, stores the txid before broadcast where the network allows, and never re-signs. Rows without a used approval never send. Why: a hijacked sign-in can't add its own phone or Telegram and withdraw, and no coin leaves without three separate proofs from the owner.
- WITHDRAW_PILOT_TESTERS_ONLY is the one switch that limits Seeds-sent withdrawals to beta testers (off: open to every member who meets the rules); a coin is added to catalog.ts only with a tested signer (ZEC has none). Why: no deposit or withdrawal path is offered that Seeds can't actually complete.
