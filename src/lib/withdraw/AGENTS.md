# Withdrawals

- Wrapped ecosystem withdrawals reuse the pinned ecosystem-tokens.ts contracts in the Ethereum registry and protected EVM sender; their price is looked up by contract, never by the native ticker, and a missing price still blocks non-tester limits. Why: wrapping does not grant a new key, bypass limits or make a native coin interchangeable with its token.

- TON payment links are parsed in ton-payment-link.ts on the form and server; only TON or pinned USDt, integer base units and plain text are accepted (no binary/init payloads). USDt comments are email-bound, stored once before approval, frozen by a DB trigger, checked against Telegram metadata before approval consumption and sending, and built as TEP-74 text by ton-jetton.ts. Why: invoice notes must reach the recipient without changing what the owner approved.

- Seeds-signed withdrawals for every coin live here: catalog.ts (coins + networks Seeds can sign; keys match deposit-options; tested), rules.ts (pure readiness, email-code digests, amounts; tested), send.server.ts (address checks, balance reads, one signer per kind), withdraw.server.ts (flow), withdraw.functions.ts. One rule set for every coin (Bobby, Nov 20 2026): the wallet link must be newer than both the newest verified authenticator and profiles.telegram_verified_at (set only by a profiles trigger; null while connected = unproven, re-link); each withdrawal needs an email code bound to an HMAC of the exact coin/network/units/address/tag (withdrawal_email_codes, single use, 10 min, 5 tries, via use_withdrawal_email_code), a fresh session TOTP, and a send_approvals 'withdrawal' Telegram tap. reserve_withdrawal stores it as 'approving'; the tap is spent and approve_pocket_withdrawal starts the level's hold; the scheduled job (/api/public/jobs/pulse-withdrawals, path kept) re-checks everything, stores the txid before broadcast where the network allows, and never re-signs. Rows without a used approval never send. Why: a hijacked sign-in can't add its own phone or Telegram and withdraw, and no coin leaves without three separate proofs from the owner.
- Every coin kind has a confirmation reading in txStatus; raw answers are judged only by confirm-rules.ts (tested), and a withdrawal is marked failed only when the network refuses it in a final block. Why: a slow or silent server must never make a sent withdrawal look failed.
- WITHDRAW_PILOT_TESTERS_ONLY is the one switch that limits Seeds-sent withdrawals to beta testers (off: open to every member who meets the rules); a coin is added to catalog.ts only with a tested signer (ZEC has none). Why: no deposit or withdrawal path is offered that Seeds can't actually complete.
- Cardano sends are built and signed in src/lib/pockets/cardano-tx.ts (pure, tested against RFC 8032): ADA-only inputs (token-carrying coins never spent), exact fee, 1 ADA fee cap, crumbs ≤0.2 ADA join the fee; I/O in cardano-io.server.ts: coin lists from Koios and NowNodes Rosetta must agree (cardano-sources.ts, tested), tip/fees/submit via Koios; key ownership checked from the account key because base addresses include the stake key. Why: tokens must never leave by accident and a wrong key must never sign.
