# src/lib/qa — Feedback & QA Center (prelaunch)

- Who: testers = TESTER_ROLES (beta + admin), checked server-side in every qa.functions.ts handler; admin side (qa-admin.functions.ts, /admin/bugs) uses requireAdmin. Why: the browser never decides access.
- Storage: rows are server-written only; `authenticated` has SELECT with owner-only policies (reporter's own reports — column grant without assignee_id, attachments, non-internal comments); qa_settings/qa_events are service-role only. Reports, attachments, comments and history are permanent (qa_guard trigger); reporter/device/page columns can't change; duplicates are one level deep. Why: a test record must stay whole and testers must only ever see their own.
- Files: private bucket qa-attachments, path {reporter}/{report}/{uuid}.{ext}; uploads only via server-issued signed upload links, refused unless getBucket says public=false (assertQaBucketPrivate, alerts the group hourly; bucketSafeForUploads tested); an attachment shows only after confirmAttachments finds the file with an allowed size/type (else it is removed). Views are 2-minute signed links. Why: no public files and no oversized or disguised uploads.
- Privacy: only what qa-rules.ts allows is stored — scrubbed page path (SAFE_QUERY_KEYS, no hash, long token-like segments hidden), browser/OS name+major version, viewport, BUILD_ID. Screenshots are taken in the browser (modern-screenshot), form fields, [data-qa-mask], QR codes, Balance/In pocket table columns and text matching mask-rules.ts (addresses/keys, 6–8 digit codes, labelled amounts) are painted black inside the capture copy before review (tag + onCloneEachNode, so blackouts follow the copy's layout); no page screenshot on SCREENSHOT_BLOCKED_PREFIXES (coin sign-in, Security, Withdraw); the tester reviews/blacks out more, nothing uploads before Send. Never read storage, cookies, form values, console or network. Why: Cory's brief — no tokens, secrets, financial data or form contents.
- Switch: qa_settings.enabled hides the button and refuses new reports (Admin → Bugs). Full rollback = remove <FeedbackButton /> in __root.tsx and the Bugs menu entry; nothing else depends on these tables.
- Unreported browser errors go to Seeds' own log (client_error_groups/client_errors, service-role only) via /api/public/client-error: same-origin, IP-capped, scrubbed in the browser and again on the server by error-log-rules.ts (tested), never from sign-in/key/security/withdraw/admin pages, account id only from a verified token; new or returning errors post to the QA group (max 10/hour); Admin → Bugs → Errors; switch qa_settings.error_log_enabled. Sentry is not used; never add it, Replay, or any outside transfer without the owner's approval. Why: error text carries amounts, addresses and memos.
- Telegram: qa_settings.telegram_chat_id (Admin → Bugs → Telegram group; saving checks the bot can see the group) gets every new report (groupReportText: escaped text excerpts, page path, reporter name, file count, link) and every status change (groupStatusText, team or tester retest); attachments never leave Seeds. No group set = short DM to verified admins. Posts are best-effort (postToQaGroup never throws). Why: the team triages in the SEEDS group, and screenshots must stay private.
