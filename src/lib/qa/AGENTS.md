# src/lib/qa — Feedback & QA Center (prelaunch)

- Who: testers = TESTER_ROLES (beta + admin), checked server-side in every qa.functions.ts handler; admin side (qa-admin.functions.ts, /admin/bugs) uses requireAdmin. Why: the browser never decides access.
- Storage: rows are server-written only; `authenticated` has SELECT with owner-only policies (reporter's own reports, attachments, non-internal comments); qa_settings/qa_events are service-role only. Reports, attachments, comments and history are permanent (qa_guard trigger); reporter/device/page columns can't change; duplicates are one level deep. Why: a test record must stay whole and testers must only ever see their own.
- Files: private bucket qa-attachments, path {reporter}/{report}/{uuid}.{ext}; uploads only via server-issued signed upload links; an attachment shows only after confirmAttachments finds the file with an allowed size/type (else it is removed). Views are 2-minute signed links. Why: no public files and no oversized or disguised uploads.
- Privacy: only what qa-rules.ts allows is stored — scrubbed page path (SAFE_QUERY_KEYS, no hash, long token-like segments hidden), browser/OS name+major version, viewport, BUILD_ID. Screenshots are taken in the browser (modern-screenshot), form fields and [data-qa-mask] are blacked out before review, the tester reviews/blacks out more, nothing uploads before Send. Never read storage, cookies, form values, console or network. Why: Cory's brief — no tokens, secrets, financial data or form contents.
- Switch: qa_settings.enabled hides the button and refuses new reports (Admin → Bugs). Full rollback = remove <FeedbackButton /> in __root.tsx and the Bugs menu entry; nothing else depends on these tables.
- Sentry is evaluated only (docs in Files); never add it, Replay, or any outside transfer without the owner's approval.
