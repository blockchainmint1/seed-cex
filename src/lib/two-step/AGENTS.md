# One swap form + two-step swaps

- /swap is the only swap form: src/lib/swap/plan.ts (pure, tested) names every route for a pair (THORChain/Maya, TSD Bridge, pool, or two-step); the page quotes each and the best output is preselected. /swap/tokens 301s to /swap. Coin pickers hand back normalizeSide, so a pool token THORChain lists is that coin. Why: one name per coin, and the server, not the page, decides what a route may do.
- Two-step swaps (pool hop + THORChain/Maya hop through a plain mid coin, MID_IDS) live in two-step.server.ts (stage machine, claimed per step, advanced by the tsd-routes minute job, the Telegram tap and My swaps) with rules in rules.ts (tested). Fixed order: server re-quote ≤1% worse than shown → reserve_two_step_swap (one open per member, swap caps) → one Telegram Approve (purpose two_step, spent once) → hop 1 via startDexLeg / sendSwapFromPocket (own pocket only, ≤2% worse than shown) → hop 2 only with the coins that arrived (min of reported payout and pocket balance) and only if a fresh price clears the agreed minimum, else kept_mid. Child rows carry two_step_id and are hidden from standalone history. Why: one tap must never authorise more than the agreed swap, and a price move leaves the member holding a plain coin, never a loss Seeds caused.
- A hop is adopted, never re-sent, only when a row tagged with this two-step swap already exists since the step started (sentSince: swap_sends.parent_id, set by reserve_swap_send from _route_id; dexSince: dex_swaps.two_step_id); an error after that point never retries the send. Other swaps may run alongside (Bobby, Nov 22). Why: a crash after broadcast must not pay twice, and a member's own separate swap must never be taken for a step (audit T1).
- Before a THORChain/Maya step 1 goes out, the pocket's middle-coin balance is noted once (two_step_swaps.mid_baseline_units, write-once, only while approved); step 2 hands on min(reported payout, balance − that baseline) via midToHandOn. Why: coins the member already held are never spent by a swap (audit T4).
- TWO_STEP_TESTERS_ONLY (rules.ts, tested) keeps two-step swaps for beta testers; inner steps skip per-swap caps because reserve_two_step_swap holds them once. Before opening to capped members, make each step check caps without double-counting. Why: audit T2, re-checking mid-swap could strand a member halfway.
