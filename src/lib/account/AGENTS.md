# Account
- Deposit picker checks every Seeds-sent network with its own authenticated withdrawal context, and depositStates never borrows a sibling network's blocker; tester-stage TRON USDT deposits require a verified clear sender, while review-stage and unknown readiness stay closed. Why: receiving must not be one-way, and an unselected network must not be labelled unavailable just because it has not been checked.
- Balances page lists every supported coin (main rows from deposit-options, "Re-link to add" for networks the link lacks) plus Ethereum/Base ERC-20s from src/lib/account/erc-tokens.ts (tested: swap-list tokens always, other held tokens via Alchemy labelled "not checked by Seeds"), 25 per page. The token read retains suspicious rows only for display; token-visibility.ts hides unverified rows by default and manages per-account browser hide/spam/remove/restore choices. Unknown token rows remain display only. Native Stellar/TON/Sui rows use the same catalog; their deposit/send gate is ed-send-rules.ts. Why: one catalog avoids duplicate rows, and restoring a spam row must never grant a send or swap action.
- A row flagged suspectedSpam shows the neutral label from token-visibility.ts (SPAM_ROW_LABEL) instead of the token's own symbol, and tokenAriaName() keeps that symbol out of tooltips and screen-reader text; the real symbol appears only after the member clicks "show name" (audit TS1). Why: a spam token's own symbol is often the phishing lure, and printing it hands the member something to read and retype.
- A row's Swap link opens /swap already filled in on the pair that coin can actually do — sell what you hold to TSD, otherwise buy it with TSD — from src/lib/account/swap-link.ts (pure, tested); pinned ecosystem tokens use their canonical symbols in URLs and the same helper resolves their Ethereum contracts; a row with no planned pair keeps the plain Swap page. Why: moving a wrapped token into the main balance catalog must not lose its prefilled pool route.
