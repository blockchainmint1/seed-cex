# Seeds AI
- Seeds AI lives in src/lib/ai/: plan.ts/theories.ts (pure engine shared by browser tester and daily server check; tested), lock-rules.ts + catalog.ts (only aiBuyable coins: THORChain route Seeds signs, or a "SEEDS:<pair>" EVM-leg TSD market), ai.server.ts (daily check, unique per plan+day so re-runs never resend), ai.functions.ts; prices download inside Postgres (ai_sync_request/ai_sync_ingest via /api/public/jobs/ai-daily schedules). ai_settings.execution_enabled (all members) stays false; beta testers' real buying is ai_settings.admin_execution_enabled. Why: the message a member gets must match the plan they tested, and no coin is offered that Seeds can't actually buy.
- "Find my playbook" (src/lib/ai/playbook.ts, pure, tested) ranks rule combinations only on the older part of the history and uses the newest slice purely to report held-up/faded; the AI write-up (playbook.functions.ts, signed-in, daily cap via ai_playbook_notes) only explains numbers the engine produced. Why: picking on the whole history is curve-fitting, and an LLM must never invent returns.
- Real buying (execute-rules.ts pure + tested, execute.server.ts): a plan with ai_plans.execute keeps a ledger built only from finished ai_plan_moves; each daily check turns target weights into queued moves that wait for the owner's OK (Telegram one-tap only up to one_tap_limit_usd via signed ai1/ai0 buttons from the owner's verified chat; bigger days confirm on /account/ai). The every-minute tsd-routes job starts approved moves one per member as ordinary startTsdRoute swaps (waitForFirstSend false), links the route id, and a failed move stops the rest of that day; a 'starting' move is reconciled to its route, never restarted. TSD from going to cash is not set aside: a buy-back short of free TSD fails with a "deposit more TSD" alert. Why: no coin moves without the owner's yes, a swap is never started twice, and the plan never spends more than it owns.
