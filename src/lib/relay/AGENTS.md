# Relay swaps (ETH <-> HYPE on HyperEVM, ETH -> TON)

- src/lib/relay/: rules.ts (pure, tested: checkRelayQuote, amounts, status mapping), relay.server.ts (quote, request, relay_swaps stage machine), relay.functions.ts. Seeds signs only a single Relay step that checkRelayQuote proves is depositNative(pocket, orderId) to RELAY_DEPOSITORY (checked on-chain on both networks) on the origin network, for exactly the reserved amount, with recipient = the same pocket and a native payout on the other network; anything else is refused. Why: Relay writes the transaction, so Seeds must prove it before signing.
- Order: server quote ≤1% worse than shown → pocket balance + fee + set-asides → reserve_relay_swap (caps, one open per member) → Telegram Approve (purpose relay_swap, spent once) → fresh quote must clear the agreed minimum → eth_call test → hash stored before broadcast (write-once trigger) → receipt → Relay status until success/refund, payout receipt checked on the destination network. Testers only (relayBlocker). Why: same no-tap-no-move and never-pay-twice rules as every other swap.
- Only native ETH <-> native HYPE for now (planSwap kind "relay"; HYPE is SwapSide kind "hype"). Why: one shared EVM address on both networks, no token approvals.
- ETH -> TON (direction to_ton, also the last step of hype_chains to_ton = TSD/coin -> ETH -> TON): the payout goes to the link's own TON pocket, compared exactly (case-sensitive) in checkRelayQuote and re-checked against the live link before the tap is spent and before signing; relay_swaps.recipient is fixed by trigger. Arrival = the pocket's TONAPI history shows one finished incoming TON transfer ≥ the agreed minimum since the swap row was created (tonPayoutSeen, tested; audit TA5); dest_baseline is still noted before signing for the record. TON -> anything is not offered (would need signing a Relay-built TON transaction). Why: the payout leaves the shared EVM address, so the other address must be proven to be the member's own.
