# src/lib

- Market orders: rules in src/lib/market-order.ts (tested); the server re-derives price protection from the live book (capped), and a market order is never open/partial (DB check orders_market_never_rests; restoreFills cancels its size). Why: a market order must never wait on the book at a stale worst-case price.
- P2P sell-ad ranges come only from offerRange (src/lib/p2p-range.ts, tested): the max buyers see is the seller's max cut to what their free pocket balance covers, ads that can't cover the min are hidden, and openTrade re-checks against the live balance. Marketplace, seller page, seller desk and save toast all use it. Why: an ad must never offer more than the pocket can actually send.
- Never pass fetch `redirect: "error"` (Workers throws on it); use `redirect: "manual"` and treat any non-2xx as a refusal (workers-fetch.test.ts). Why: it works in the dev server but broke SNS signature checks on the live site.
- Never keep an unfinished promise in module memory for another request to await (Workers drops cross-request promises: "This promise was created by a request that has since ended"); module caches hold finished values only. TXC/ISK scantxoutset retries briefly when the node says a scan is in progress (rpc.server.ts) and never reuses a finished answer. Why: shared promises blanked /markets on the live site; the node refuses concurrent scans; coin selection must stay current.
- Blockchain server lists live only in src/lib/nodes.server.ts (tested): paid providers first (Alchemy via ALCHEMY_KEY, NowNodes via NOWNODES_API_KEY, Liquify THORNode via LIQUIFY_API_KEY and Liquify Midgard via LIQUIFY_MIDGARD, both in a header), public servers last; a second address for the same machine is backupOnly and never counts as a second confirmation; reads fail over on any error, broadcasts only when a server didn't answer (shouldFailOver). Never log a full endpoint URL (Alchemy's key is in the path). Why: paid nodes are faster and don't rate-limit, and a refused send must never be re-sent elsewhere.
- Public unauthenticated endpoints that fan out (visit counter, swap/TSD/DEX quotes) are capped per connection via ip-rate.server.ts (hashed IP in api_rate_buckets, 10 minutes; limits in ip-rate.ts, tested). Why: anyone can call them, and each call costs paid node and bridge requests.
- Honest.Money's hm.js and help widget load only on the public info pages in src/lib/third-party-scripts.ts (tested) via site/HonestMoneyScripts.tsx; leaving such a page for any other reloads it. Why: third-party code must never run beside sign-in, keys, trading or admin.
- THORChain market data (prices, 24h stats, candles) lives in src/lib/markets/: thor-markets.ts (catalog of primary coin/TSD markets + pure candle rules; tested), thor-markets.server.ts (Midgard reads, cached), thor-markets.functions.ts (public, IP-capped). Prices are THORChain's dollar price shown as TSD; chart buttons are ranges (CHART_RANGES: 1D/7D/1M from the pool's own candles, 3M/1Y/All from CoinMarketCap daily history via shared(), All merged into Monday weeks) and the open candle follows the live pool price. Why the split: Midgard's day history has month-long holes (pool halts) and one-off spikes real markets never had. Pages load market rows in the loader and hand them to useQuery as initialData (no SSR query hydration in this app). Why: one source for every chart and price, and a page must never disagree with itself.
- /admin/plan (business plan): text in src/lib/business-plan.server.ts, served only by admin-gated getBusinessPlan with live counts; calculators in business-plan.ts (tested), page body in components/admin/BusinessPlanView.tsx; research write-ups (e.g. /admin/plan/lbtc) are *.server.tsx rendered to HTML by an admin-gated server fn. Why: strategy must not ship in the public JS bundle, and money math must match listing.ts prices.
- Seeds' own market history: written every 5 minutes by the cron job at /api/public/jobs/market-snapshot (src/lib/markets/snapshot.server.ts) into market_snapshots_5min / chain_snapshots / network_snapshots, with an hourly rollup and pruning; row shapes, unit conversion (THORChain 1e8 base units → whole coins) and what is worth storing are decided by snapshot-rules.ts (tested). Pages read the newest slice through market_snapshot_latest (snapshot-read.server.ts + snapshot-read-rules.ts, tested) and fall back to THORChain when it is stale, incomplete or unreadable. Why: the history must match what visitors were shown, a stale or half-empty slice must never be presented as live, and these tables hold no member data — server role only, no browser access.
- Beta testers = user_roles 'beta' plus every admin (TESTER_ROLES in admin-guard.ts; set only via set_beta_role from Admin → Admin access, logged in admin_role_events). Pilot money paths (swaps, TSD swaps, Seeds AI real buying, PulseChain withdrawals) gate on pilotTesterAccess (role only, no fresh admin code), and testers get no Seeds limits: swapLimitsFor(true) / testerLimits (no amount cap, no withdrawal hold; two-factor rules and admin pauses still apply). Why: Bobby's call (Nov 19 2026) to test with real money without caps; account-protection rules are not limits.
- Display data shared by many visitors (market summary/book/tape/stats/series, TXC node status, CMC prices, pocket balances) goes through shared() in src/lib/cache/shared-cache.server.ts (rules + times in shared-cache-rules.ts, tested): per-instance memory for a few seconds, then the server-only shared_cache row, refreshed by one claimed caller while others see the previous copy; a failed/offline answer never replaces a good copy. Wrap only the display server functions, never the underlying *.server reads: sends, settlement, set-asides, gas checks, reservations and limits always read live. Members' Refresh passes fresh (honored once a copy is 10 s old). Why: 50,000 visitors must cost a handful of database and blockchain reads, not one per screen.
- TXC/ISK coin reads: mempool.texitcoin.org is Seeds' own TXC mempool stack (workspace project "TXC mempool": node + address indexer), so loadUtxosFor (sends, settlement, set-asides, TSD carrier fee coins) reads TXC from its indexer first, but only when indexerUsableForSend passes (indexer's _status tip ≥ our node's getblockcount, list not x-truncated) and checkCoinsAgainstNode passes (one batched gettxout per coin on our node: size and owner script must match exactly, spent/unconfirmed coins dropped, ≤ MAX_COINS_TO_VERIFY coins; utxo/explorer-rules.ts, tested; exception: the pocket's own change still in the mempool counts only when Seeds itself broadcast its parent (seeds_broadcasts via utxo/seeds-made.server.ts, recorded at every broadcast; audit X1 — a member-made parent could be replaced) and our node shows the same address signed every input and gettxout matches — selfChangeCoins, added only to a list whose mempool-spent coins were dropped; Litecoin/Bitcoin/Dogecoin/Bitcoin Cash sends read Blockbook through utxo/book-self-change*.ts, which counts own change only when every input is this same address and drops the confirmed coin it spent; TSD payments use the smallest coin that covers the fee (utxo/carrier-coins.ts) and, when the pocket has fewer than 2 fee coins, return change as up to 5 × 0.01 TXC fee coins + the rest (utxo/fee-coins.ts, tested), sent only if omni_decodetransaction reads it back as the same Simple Send from→to/property/amount, else the plain payment is used; a plain payment the node reads back differently is refused), else our node's scantxoutset (its coins also go through the same gettxout batch so mempool-spent coins are dropped); callers pass atLeast so a short fast list is rechecked by the scan before "not enough". ISK sends use our node first; the explorer is the fallback when the node is down. loadDisplayUtxosFor (balances, deposit alerts, P2P "funds verified", seller desk) reads TXC/ISK explorers first (~150 ms). Every TXC/ISK/LTC send (buildAndSignTransfer and Omni carriers, which now pay the going rate) is refused before signing above the per-chain ceiling in utxo/fee-cap.ts (tested). Why: legacy signatures don't cover input amounts, so an understated coin would become miner fee; our node stays the source of truth for anything signed, and scantxoutset (~10 s, one at a time) is only the fallback.
- Coin research on /markets/$slug (recent pool trades, cost by size, my activity, CoinMarketCap market data/links/exchanges/news, team-picked videos): pure parsing + trust rules in src/lib/markets/coin-research.ts (tested: CMC by id never ticker, outlier/excluded markets dropped, http(s) links only, referral query strings stripped, only finished swaps), reads in coin-research.server.ts through shared() (CACHE_TIMES poolTrades/costQuotes/coinProfiles/coinPairs/coinNews), "My activity" reads the member's own rows as the member. Videos live in coin_videos: public column-limited SELECT, writes only via admin-gated coin-videos.functions.ts (YouTube oEmbed must describe the video); the player loads only on press (youtube-nocookie). Why: outside data must be labelled and cached so visitors never multiply paid calls, and nothing third-party runs until a visitor asks for it.
- Primary markets (/markets) merges THORChain rows with the home-coin order books (TXC/ISK/ZCU vs TSD) through src/lib/markets/primary-rows.ts (tested: true 24h window, book mid only before a first trade and labelled, column sort with missing figures last); home-coin rows come only from Seeds' own book/trades via getHomeCoinMarkets (shared()). Why: THORChain doesn't trade these coins, and a quiet book must never look like live 24h activity.
- Set-asides (src/lib/set-asides.ts pure + tested, set-asides.server.ts): coins promised to open orders, unsent exchange-trade legs and live P2P sales count as "In trades"; a trade leg or P2P release whose approval already carries a txid no longer counts (audit C1). "Going out" (audit C3) adds withdrawals in approving/held, DEX/two-step swaps awaiting approval, and live swap_out/loan approvals; it counts against new spends but not in the order watch (watchTotal), and an approved send passes exceptApprovalId so it never blocks itself. Every Seeds-made spend that isn't paying one of them (new orders, P2P opens, withdrawals, THORChain/Maya, TSD, DEX and two-step swaps, loan collateral/funding; not loan repayments) must pass setAsideFor / pocketSpendProblem, failing closed, and runs its check + hold inside withPocketSpendLock (lease row pocket_spend_locks, audit C2; never nest two for one member). The every-minute order watch (order-cover.server.ts) cancels the newest uncovered orders only when explorer and node both show the shortfall on two runs at least 45 s apart (coverStrike, order_cover_flags), then tells the member. Why: Seeds can't lock coins it doesn't hold, so its own books must never promise the same coin twice or cancel orders over a send it just made.
- Ignite: ignite.functions.ts + nectarpay.server.ts, Peer Pay in ignite-peer.ts (tested) + ignite-peer.functions.ts; rows server-written; a seat is confirmed only in ignite-confirm.server.ts, which re-reads the NectarPay invoice (paid in full, Seeds' order id) and confirms with compare-and-set, via the signed webhook or throttled re-check; one live checkout per seat, but a payment on an earlier checkout of the same seat still counts (found via the order id NectarPay's API reports for that invoice; a second payment is flagged for refund). Admins cancel via cancelIgniteSeat; cancelled seats never re-confirm (canConfirmSeat); refunds manual in NectarPay. Why: payment state never comes from the browser, a missed webhook can't strand a seat, no seat is paid or announced twice.
- Listings (/list, Admin → Listings): live prices in listing_prices (admin-edited, public read), promo codes in listing_promo_codes (server-only, claimed atomically by claim_listing_promo, never deleted); each application stores price, discount and amount at insert (trigger-locked). NectarPay checkout opens right after applying (listing-pay.server.ts), every invoice is remembered in listing_invoices, the shared webhook routes listing invoices before Ignite, and a payment counts only after re-reading the invoice from the API. Why: a payment on any checkout must never be lost or counted twice. Payment return addresses, shared pay links and wallet/key pairing manifest URLs use safeOrigin from safe-origin.ts only (Seeds' own hosts; tested). Why: a browser-sent look-alike host must never receive a payer.
- Affiliates (/admin/affiliates): rules in affiliates.ts (tested). A new member's invite code is recorded once in referrals (first code wins, only within REFERRAL_WINDOW_MS of joining, never their own) from SSO sign-up, joining HME later, or the browser's saved code after sign-in (ReferralCapture: hm_ref first, then Seeds' own seeds_ref); /invite/{code} counts people-only clicks per day (bots skipped, IP-capped, 10-minute repeat dedupe) and sets seeds_ref; code owners come from Honest.Money member-check by permanent member id (codesFromMemberCheck: exact id, approved, valid username only), synced via syncReferralOwners for members not checked in a day (5-minute job + Affiliates load; referral_code_checks), and also when a member opens their own invite link (only that sets viewed_at, shown as "link opened"); matched-but-unused codes don't get table rows. Trading/swap totals come only from admin_member_activity (called-off matches and two-step legs excluded); TSD is read live through the shared cache, capped per view. Class seats and listing applications are credited by purchaseRefCode (code used at checkout, else the buyer's referrals code, never their own; mirrored in admin_affiliates SQL); listing_applications.ref_code is server-written; set-up = active hme_link, finished = onboarding done. Members see only their own codes' totals on Account → Referrals (myReferralStats: counts and class/listing dollars; myReferralPeople: each referred member's username, join date, wallet linked, setup finished; never balances or trade amounts of referred people). All tables server-only. Why: HME keeps the official credit, but admins need to see who shares and what referred members do, without storing visitor details.
- The class program is shown to members as To the Moon at /to-the-moon and /to-the-moon/<class>; code, tables and email lists keep their ignite_ names, and old /ignite, /ignite/<class> and /ignite/confirmed links 301 via to-the-moon-paths.ts (tested; maps renamed class addresses). Why: open checkouts, emails and referral links still carry /ignite, and renaming stored data would break history.
- The class program (internally "Ignite") is a series of classes: ignite_classes (public SELECT for non-draft only; admin-written via ignite-classes.functions.ts), one registration row per member carrying class_id + fee/miner discount/deposit/amount priced on the server by priceSeat (ignite.server.ts) from the stored class; a live checkout keeps its class and amount (switchBlock), a full payment below the seat price is held as underpaid, never confirmed. Miner waiver: ignite_miner_marks (admin) beats Honest.Money's signed POST /api/public/hme/members/mining (needs mining:read on the Seeds key; mining=true → waive, mining=false+complete=true → not a miner, anything else = unknown = full fee). Unpaid/interested people live in ignite_interest (service-role only, class-independent, unsubscribe via the signed "ignite" email list). Instructor photos sit in the private ignite-media bucket, served by /api/public/ignite-photo/$id. Why: price, seats and who-pays-what must come only from the stored class, and nobody is charged as a non-miner because a lookup failed silently.
- Ignite seat notices (confirmed email, Telegram note, Honest.Money purchase report) go only through sendSeatNotices in ignite-confirm.server.ts: each claimed once in alert_log, seat marked notices_done_at, and the minute job (send-approvals) finishes seats left undone 2 min–3 days after confirming (seatNoticesDue, tested). Why: a payment notice cut off after the seat was marked paid lost the email (one member, Nov 23 2026).
- To the Moon miner check (minerStatusFor): every non-answer is "unknown" (full fee), recorded in miner_check_health and logged to Admin → Bugs → Errors at most every 5 min; "unknown" is cached 30 s only; admin seat moves go through seatMoveProblem (no finished/full classes, drafts need explicit OK). Why: auditor K1/K4 — a broken check must be seen the same day, and seats must never overfill.
- To the Moon registrants can be hidden (ignite_registrations.hidden_at, setIgniteSeatHidden, hideBlock in ignite-admin.ts, tested) instead of deleted: only pending/cancelled rows without an open checkout; a trigger and re-registration un-hide. The minute job (send-approvals → sweepLapsedCheckouts) hides unpaid sign-ups once checkoutLapsed (tested: checkout over 5 min gone, no open Peer Pay link) and adds them to ignite_interest. Why: deleting cascades away email history and peer-pay links, and late payments must still count.
