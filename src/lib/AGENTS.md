# src/lib

- Market orders: rules in src/lib/market-order.ts (tested); the server re-derives price protection from the live book (capped), and a market order is never open/partial (DB check orders_market_never_rests; restoreFills cancels its size). Why: a market order must never wait on the book at a stale worst-case price.
- P2P sell-ad ranges come only from offerRange (src/lib/p2p-range.ts, tested): the max buyers see is the seller's max cut to what their free pocket balance covers, ads that can't cover the min are hidden, and openTrade re-checks against the live balance. Marketplace, seller page, seller desk and save toast all use it. Why: an ad must never offer more than the pocket can actually send.
- Never keep an unfinished promise in module memory for another request to await (Workers drops cross-request promises: "This promise was created by a request that has since ended"); module caches hold finished values only. TXC/ISK scantxoutset retries briefly when the node says a scan is in progress (rpc.server.ts) and never reuses a finished answer. Why: shared promises blanked /markets on the live site; the node refuses concurrent scans; coin selection must stay current.
- Blockchain server lists live only in src/lib/nodes.server.ts (tested): paid providers first (Alchemy via ALCHEMY_KEY, NowNodes via NOWNODES_API_KEY), public servers last; reads fail over on any error, broadcasts only when a server didn't answer (shouldFailOver). Never log a full endpoint URL (Alchemy's key is in the path). Why: paid nodes are faster and don't rate-limit, and a refused send must never be re-sent elsewhere.
- Public unauthenticated endpoints that fan out (visit counter, swap/TSD/DEX quotes) are capped per connection via ip-rate.server.ts (hashed IP in api_rate_buckets, 10 minutes; limits in ip-rate.ts, tested). Why: anyone can call them, and each call costs paid node and bridge requests.
- Honest.Money's hm.js and help widget load only on the public info pages in src/lib/third-party-scripts.ts (tested) via site/HonestMoneyScripts.tsx; leaving such a page for any other reloads it. Why: third-party code must never run beside sign-in, keys, trading or admin.
- THORChain market data (prices, 24h stats, candles) lives in src/lib/markets/: thor-markets.ts (catalog of primary coin/TSD markets + pure candle rules; tested), thor-markets.server.ts (Midgard reads, cached), thor-markets.functions.ts (public, IP-capped). Prices are THORChain's dollar price shown as TSD; weekly candles are built from daily ones (Midgard's own weekly candles are wrong) and the open candle follows the live pool price. Pages load market rows in the loader and hand them to useQuery as initialData (no SSR query hydration in this app). Why: one source for every chart and price, and a page must never disagree with itself.
- /admin/plan (business plan): text in src/lib/business-plan.server.ts, served only by admin-gated getBusinessPlan with live counts; calculators in business-plan.ts (tested), page body in components/admin/BusinessPlanView.tsx; research write-ups (e.g. /admin/plan/lbtc) are *.server.tsx rendered to HTML by an admin-gated server fn. Why: strategy must not ship in the public JS bundle, and money math must match listing.ts prices.
