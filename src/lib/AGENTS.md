# src/lib

- Market orders: rules in src/lib/market-order.ts (tested); the server re-derives price protection from the live book (capped), and a market order is never open/partial (DB check orders_market_never_rests; restoreFills cancels its size). Why: a market order must never wait on the book at a stale worst-case price.
- P2P sell-ad ranges come only from offerRange (src/lib/p2p-range.ts, tested): the max buyers see is the seller's max cut to what their free pocket balance covers, ads that can't cover the min are hidden, and openTrade re-checks against the live balance. Marketplace, seller page, seller desk and save toast all use it. Why: an ad must never offer more than the pocket can actually send.
- Never keep an unfinished promise in module memory for another request to await (Workers drops cross-request promises: "This promise was created by a request that has since ended"); module caches hold finished values only. TXC/ISK scantxoutset retries briefly when the node says a scan is in progress (rpc.server.ts) and never reuses a finished answer. Why: shared promises blanked /markets on the live site; the node refuses concurrent scans; coin selection must stay current.
- Blockchain server lists live only in src/lib/nodes.server.ts (tested): paid providers first (Alchemy via ALCHEMY_KEY, NowNodes via NOWNODES_API_KEY, Liquify THORNode via LIQUIFY_API_KEY and Liquify Midgard via LIQUIFY_MIDGARD, both in a header), public servers last; a second address for the same machine is backupOnly and never counts as a second confirmation; reads fail over on any error, broadcasts only when a server didn't answer (shouldFailOver). Never log a full endpoint URL (Alchemy's key is in the path). Why: paid nodes are faster and don't rate-limit, and a refused send must never be re-sent elsewhere.
- Public unauthenticated endpoints that fan out (visit counter, swap/TSD/DEX quotes) are capped per connection via ip-rate.server.ts (hashed IP in api_rate_buckets, 10 minutes; limits in ip-rate.ts, tested). Why: anyone can call them, and each call costs paid node and bridge requests.
- Honest.Money's hm.js and help widget load only on the public info pages in src/lib/third-party-scripts.ts (tested) via site/HonestMoneyScripts.tsx; leaving such a page for any other reloads it. Why: third-party code must never run beside sign-in, keys, trading or admin.
- THORChain market data (prices, 24h stats, candles) lives in src/lib/markets/: thor-markets.ts (catalog of primary coin/TSD markets + pure candle rules; tested), thor-markets.server.ts (Midgard reads, cached), thor-markets.functions.ts (public, IP-capped). Prices are THORChain's dollar price shown as TSD; weekly candles are built from daily ones (Midgard's own weekly candles are wrong) and the open candle follows the live pool price. Pages load market rows in the loader and hand them to useQuery as initialData (no SSR query hydration in this app). Why: one source for every chart and price, and a page must never disagree with itself.
- /admin/plan (business plan): text in src/lib/business-plan.server.ts, served only by admin-gated getBusinessPlan with live counts; calculators in business-plan.ts (tested), page body in components/admin/BusinessPlanView.tsx; research write-ups (e.g. /admin/plan/lbtc) are *.server.tsx rendered to HTML by an admin-gated server fn. Why: strategy must not ship in the public JS bundle, and money math must match listing.ts prices.
- Seeds' own market history: written every 5 minutes by the cron job at /api/public/jobs/market-snapshot (src/lib/markets/snapshot.server.ts) into market_snapshots_5min / chain_snapshots / network_snapshots, with an hourly rollup and pruning; row shapes, unit conversion (THORChain 1e8 base units → whole coins) and what is worth storing are decided by snapshot-rules.ts (tested). Pages read the newest slice through market_snapshot_latest (snapshot-read.server.ts + snapshot-read-rules.ts, tested) and fall back to THORChain when it is stale, incomplete or unreadable. Why: the history must match what visitors were shown, a stale or half-empty slice must never be presented as live, and these tables hold no member data — server role only, no browser access.
- Beta testers = user_roles 'beta' plus every admin (TESTER_ROLES in admin-guard.ts; set only via set_beta_role from Admin → Admin access, logged in admin_role_events). Pilot money paths (swaps, TSD swaps, Seeds AI real buying, PulseChain withdrawals) gate on pilotTesterAccess (role only, no fresh admin code), and testers get no Seeds limits: swapLimitsFor(true) / testerLimits (no amount cap, no withdrawal hold; two-factor rules and admin pauses still apply). Why: Bobby's call (Nov 19 2026) to test with real money without caps; account-protection rules are not limits.
- Display data shared by many visitors (market summary/book/tape/stats/series, TXC node status, CMC prices, pocket balances) goes through shared() in src/lib/cache/shared-cache.server.ts (rules + times in shared-cache-rules.ts, tested): per-instance memory for a few seconds, then the server-only shared_cache row, refreshed by one claimed caller while others see the previous copy; a failed/offline answer never replaces a good copy. Wrap only the display server functions, never the underlying *.server reads: sends, settlement, set-asides, gas checks, reservations and limits always read live. Members' Refresh passes fresh (honored once a copy is 10 s old). Why: 50,000 visitors must cost a handful of database and blockchain reads, not one per screen.
- TXC/ISK coin reads: loadUtxosFor (sends, settlement, set-asides) uses our node's scantxoutset first and the public explorer (utxo/explorer-rules.ts, tested: confirmed coins only, malformed reply rejected) only when the node is down; loadDisplayUtxosFor (balance displays, deposit alerts) reads ISK from mempool.iskandercoin.com's address index first. Why: the ISK node runs one full scan at a time, which capped signed-in ISK users; coin selection still trusts our own node.
- Coin research on /markets/$slug (recent pool trades, cost by size, my activity, CoinMarketCap market data/links/exchanges/news, team-picked videos): pure parsing + trust rules in src/lib/markets/coin-research.ts (tested: CMC by id never ticker, outlier/excluded markets dropped, http(s) links only, referral query strings stripped, only finished swaps), reads in coin-research.server.ts through shared() (CACHE_TIMES poolTrades/costQuotes/coinProfiles/coinPairs/coinNews), "My activity" reads the member's own rows as the member. Videos live in coin_videos: public column-limited SELECT, writes only via admin-gated coin-videos.functions.ts (YouTube oEmbed must describe the video); the player loads only on press (youtube-nocookie). Why: outside data must be labelled and cached so visitors never multiply paid calls, and nothing third-party runs until a visitor asks for it.
