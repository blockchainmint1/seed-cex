# Key sign-in (coin / outside wallet)

- "Start with a coin" / "Use another wallet" accounts are made only through the Seeds Key hand-off: /key-signin starts a single-use request (browser keeps a secret, server stores its hash), the separate Seeds Key page POSTs /api/public/key-signin/submit with a keySigninMessage signature (coin = TXC m/44'/696969'/0'/0/0, evm = personal_sign, sol = ed25519) plus a sealed hm-link-delegate access payload, and only the starting browser can claim the session. Rules (pocket numbering, re-sign-in keeps the link, placeholder emails, wallet-pocket message) live in rules.ts (tested); the Key page copies rules.ts + seeds-key-reference.ts + src/lib/pockets/ unchanged (docs/seeds-key-page.md, test vectors in handoff.test.ts). Why: Seeds must never receive a recovery phrase, and both sides must derive identical pockets.
- Coin/wallet accounts are found by profiles (identity_kind, identity_address), never by email; their auth email is a non-deliverable placeholder that every send path skips (isPlaceholderEmail in loadRecipient/deliver) and UI hides (shownEmail). A real email is added only via a confirmed code (account_email_codes) or by attaching an HME membership with both the live session token and a signed HME ticket (attach.server.ts). Why: anyone can make a phrase, so identity is the key itself, and accounts never merge on email alone.
- Never change walletPocketMessage or the Seeds Key host once members use it. Why: outside-wallet pockets are rebuilt from that exact signature; a change strands their coins.
