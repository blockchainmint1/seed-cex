# Monero

- Monero uses two Seeds servers behind HTTPS proxies: a watch server (monerod + monero-wallet-rpc, MONERO_WALLET_RPC_URL/_TOKEN) holding VIEW-ONLY wallets (file passwords from MONERO_WALLET_FILE_SECRET, never the RPC token), and a separate offline signer wallet-rpc with a RAM-only wallet directory (MONERO_SIGNER_RPC_URL/_TOKEN, must differ from the watch server). Sends are cold-signed (wallet.server.ts sendMonero): watch exports outputs → signer loads the spend key into a throwaway wallet with a random never-stored password, imports outputs, exports key images → watch imports them and builds an unsigned set → Seeds checks describe_transfer (previewFromDescribe/previewProblem, tested: one tx, recipient, amount, change back to the pocket, fee cap) → signer signs, closes without saving → txid recorded → watch submits. Watch wallets are created once per member by /api/public/jobs/monero, the only scheduled pocket-key unlock (audit Z3, accepted). Every call holds monero_take_lease. Deposits and withdrawals stay closed until both servers are set (moneroSignerReady) and the member's watch wallet is ready. Why: the spend key must never sit on a disk or reach the server that's online (audit Z1/Z2), and no deposit may be one-way.
